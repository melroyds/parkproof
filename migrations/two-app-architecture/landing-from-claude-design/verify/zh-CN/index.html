签名核对

核对一份 ParkProof 记录的签名。

每份 ParkProof 证据 PDF 都带有数字签名附录，每条记录也都可以保存为证据文件。本页面向任何人（例如市议会工作人员、保险公司、法院书记员或驾驶员本人）说明，如何离线核对一条记录自 ParkProof 签名以来没有改动。

诚实表态。 有效的签名表明的是完整性：已签名的详情和照片指纹与 ParkProof 在签名时间签名的内容完全一致。它不表明记录是真实的（AI 可能读错了标志），不表明谁在驾驶、车停在哪里，也不表明车辆何时到达或离开，更不决定这条记录有多大分量。那由审阅的人判断。

你在核对什么

ParkProof 记录是分成几个部分签名的，这些部分称为环节。环节 0 在 ParkProof 收到保存的记录时签名。之后的每个环节（例如停车时的补充信息、车况照片、付款凭证照片或离开）在 ParkProof 收到时签名，并带有前一个环节的 SHA-256，因此各环节连成一条链。每个环节都有一个负载（被签名的确切文本，包括其照片的 SHA-256 指纹）和一个用 ParkProof 私钥（ECDSA P-256）生成的签名，该私钥从不离开 AWS KMS。证据 PDF 在签名附录中打印每个环节。记录的证据文件（驾驶员可以在应用中的记录页面下载的 .json 文件）包含同样的负载和签名，以及原始照片。

核对签名所需的公钥发布在 /parkproof-public-key.pem。请在浏览器中打开以确认能加载，然后保存下来。

你需要的

  • 证据 PDF 或证据文件，由提交记录的人提供。核对照片需要证据文件。
  • openssl。macOS 和大多数 Linux 系统自带。在 Windows 上，Git for Windows（Git Bash）或 WSL 中都有。
  • 几分钟时间。

一步一步

在 PDF 中翻到末尾的签名附录。每个环节有三块内容：文本形式的负载、base64 形式的负载和 base64 形式的签名。把环节 0 的两块 base64 内容复制到名为 link0-payload.b64 和 link0-sig.b64 的文件中，然后运行：

# 1. 解码负载。base64 -d 会忽略 PDF 中的换行。
base64 -d link0-payload.b64 > link0-payload.txt

# 2. 解码签名。
base64 -d link0-sig.b64 > link0-sig.bin

# 3. 下载 ParkProof 的公钥。
curl -O https://www.parkproof.com.au/parkproof-public-key.pem

# 4. 核对签名。预期输出 "Verified OK"。
openssl dgst -sha256 -verify parkproof-public-key.pem \
  -signature link0-sig.bin link0-payload.txt

对每个环节用它自己的文件名（link1-payload.b64、link1-sig.b64 等）重复第 1、2、4 步。不要复制可读的负载文本来代替 base64 块：PDF 会把长行折行，字节因此改变，核对就会失败。

在 Windows 上

在 cmd 或 PowerShell 中没有 base64 -d。请用 Windows 自带的 certutil 解码；在 PowerShell 中，请输入 curl.exe 而不是 curl。你也可以在 Git Bash 中按原样运行本页的所有命令。

certutil -decode link0-payload.b64 link0-payload.txt
certutil -decode link0-sig.b64 link0-sig.bin
curl.exe -O https://www.parkproof.com.au/parkproof-public-key.pem

核对各环节按顺序相连

环节 0 之后的每个环节都带有 parent_payload_sha256，即前一个环节负载的 SHA-256。打印每个负载文件的 SHA-256，并与下一个环节中的值比较。

# 5. 打印环节 0 负载的 SHA-256。
openssl dgst -sha256 link0-payload.txt
# "=" 后面的值必须等于环节 1 中的 parent_payload_sha256。
# 对后面的每个环节都这样做。

如果两个环节的编号相同（2a 和 2b），说明两台设备在链中的同一处各添加了一个部分。它们指向同一个前一环节。

核对照片

签名针对的是每张照片的 SHA-256 指纹，而不是图像本身。PDF 中打印的照片是重新编码的副本，字节永远不会一致。要核对照片，请使用记录的证据文件。文件在 photos 下列出每张照片，包括它的 sha256、为它签名的环节（signed_in）以及 base64 形式的原始字节（bytes_base64）。文件名以 parkproof-evidence- 开头，后面是记录 ID 的开头部分。下面的命令把它称为 evidence.json。

# 6. 用 jq（一个免费的 JSON 工具）从文件中取出第一张照片。
jq -r '.photos[0].bytes_base64' evidence.json | base64 -d > photo1.jpg

# 7. 打印它的 SHA-256。
openssl dgst -sha256 photo1.jpg

# 8. 查看哪个环节、哪个字段为它签名。
jq '.photos[0].signed_in' evidence.json

这个十六进制值必须等于 signed_in 中每个环节的已签名负载里这张照片的 sha256：环节 0 中的 sign_photo_sha256、car_photo_sha256 或 ambient_photo_sha256，或后续环节中 photos、photo 或 return_photos 下的 sha256。请与你在第 4 步核对过签名的那个负载比较，而不只是与文件中照片旁边的 sha256 比较，后者没有签名。第二张照片用 .photos[1]，依此类推。

如果没有 jq，可以用文本编辑器打开文件，把某张照片的 bytes_base64 值复制到名为 photo1.b64 的文件中，然后运行 base64 -d photo1.b64 > photo1.jpg。

在 Windows 上

在 Windows 上，PowerShell 可以直接读取这个文件：

$e = Get-Content evidence.json -Raw | ConvertFrom-Json
[IO.File]::WriteAllBytes((Join-Path $PWD 'photo1.jpg'), [Convert]::FromBase64String($e.photos[0].bytes_base64))
certutil -hashfile photo1.jpg SHA256
$e.photos[0].signed_in
照片核对是单独的一步。 Verified OK 表明负载中的指纹没有改动。只有重新计算原始照片的哈希，才能表明照片就是被签名的那张。如果哈希不一致，那张照片就不是 ParkProof 签名的那张，即使签名核对通过也是如此。如果文件中某张照片没有字节（bytes 为 not_on_this_device，或者对于驾驶员选择不包含的许可证照片为 withheld_permit），就无法用它核对那张照片。

用证据文件代替 PDF

证据文件也以 base64 形式包含每个环节的负载和签名，所以不用 PDF 也能完成第 1 到 5 步。从文件中取出环节 0，然后按上面的说明运行第 3 到 5 步：

jq -r '.links[0].canonical_payload_base64' evidence.json | base64 -d > link0-payload.txt
jq -r '.links[0].signature_base64' evidence.json | base64 -d > link0-sig.bin

在 PowerShell 中：

$e = Get-Content evidence.json -Raw | ConvertFrom-Json
[IO.File]::WriteAllBytes((Join-Path $PWD 'link0-payload.txt'), [Convert]::FromBase64String($e.links[0].canonical_payload_base64))
[IO.File]::WriteAllBytes((Join-Path $PWD 'link0-sig.bin'), [Convert]::FromBase64String($e.links[0].signature_base64))

结果意味着什么

签名有效 通过

Verified OK：负载正是 ParkProof 签名的内容。其中的详情和照片指纹自 ParkProof 在负载内的 signed_at 时间签名以来没有改动。照片本身在第 6 到 8 步中核对。

失败 不通过

Verification failure：负载或签名不是 ParkProof 签名的内容。记录可能被改动过，也可能是复制时出了错。在下结论之前，请完整地重新复制 base64 块并重试。

不止"字节是否改变?"

有效的签名表明完整性。它不表明：

  • AI 是否正确读取了标志。ParkProof 扫描是机器对停车标志的读取,机器可能出错。记录中的判定文本和规则是 AI 在扫描时的最佳读取,而非绝对真相。
  • 照片是否如其所述。有效的签名表明照片指纹自 ParkProof 签名以来没有改动，重新计算哈希可以表明照片是否与其指纹一致。两者都不表明照片是诚实拍摄的。
  • 任何法律结果。证据是否支持申诉、退款或诉讼,是审阅者的判断。ParkProof 是一个工具,不是律师。
  • 车停在哪里，车辆何时到达或离开，或者谁在驾驶。记录中的位置来自驾驶员的手机，或由驾驶员手动输入。标为手机时间的时间来自驾驶员的手机，ParkProof 的签名时间是 ParkProof 收到每个部分的时间。

为什么存在

大多数生成"证据"的停车应用只产出截图。截图在拍下到发送之间的任何时候都可能被编辑。数字签名的区别在于："这是我看到的"和"这是我看到的，任何人都可以核对它自 ParkProof 签名以来没有改动"。

公钥已公开发布，所以你保存它之后，核对可以离线进行，不需要我们的应用。签名时间来自 ParkProof 的服务器时钟，所以对于这个时间，你依赖的是 ParkProof。即使多年以后 ParkProof 不再运行，只要你保存了公钥副本并且有 openssl，就可以进行核对。
